# Юридический AI-помощник для Tilda

Русскоязычный чат для первичного обсуждения юридических вопросов. Сервер Node.js хранит ключ AI-провайдера; виджет Tilda открывает изолированный iframe. Никаких ключей в HTML.

## Статус

Проект подготовлен к развёртыванию, но не является уже запущенным сервисом. Добавление исходников в GitHub не запускает backend. Тесты необходимо выполнить локально или в вашей CI; их наличие не означает, что они были выполнены автором загрузки.

Модель не подключена к правовой базе и не проверяет актуальность законодательства. Ответы требуют проверки юристом. По умолчанию используется API OpenAI, а не российский AI-провайдер. Проверьте доступность провайдера и условия обработки данных для вашей ситуации.

## Файлы

- `server.js` — статические файлы, `/api/chat`, `/healthz`, валидация, ограничения и тайм-аут.
- `public/index.html`, `chat.js`, `chat.css` — интерфейс чата.
- `public/widget.js` — кнопка и iframe для Tilda, изоляция оформления через Shadow DOM.
- `tilda/embed.html` — код блока T123.
- `test/server.test.js` — тесты API без обращения к платному провайдеру.
- `Dockerfile` — контейнер для хостинга.

## Локальный запуск

Установите Node.js 24. Внешних npm-зависимостей нет.

```bash
cp .env.example .env
# Заполните .env в редакторе; не публикуйте настоящий ключ.
npm test
npm run check
npm run dev
```

Откройте `http://localhost:3000`. `npm run dev` загружает локальный `.env`. `npm start` предназначен для хостинга, где переменные уже заданы в окружении.

Для Windows можно скопировать `.env.example` в `.env` через проводник. Никакой `npm install` для запуска не требуется. Lock-файл не добавлен: внешних зависимостей нет; не используйте `npm ci` без lock-файла.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Секретный API-ключ, только на сервере |
| `OPENAI_MODEL` | Модель с поддержкой Chat Completions; по умолчанию `gpt-4o-mini` |
| `AI_BASE_URL` | Базовый URL совместимого API, по умолчанию `https://api.openai.com/v1` |
| `PORT` | Порт сервера, по умолчанию 3000 |
| `PUBLIC_ORIGIN` | Публичный origin backend, например `https://chat.example.com`, без пути |
| `ALLOWED_ORIGINS` | Дополнительные разрешённые origin для прямых запросов, через запятую; для iframe не требуется |
| `COMPANY_NAME` | Название в интерфейсе |
| `CONTACT_URL` | HTTPS-адрес страницы контактов компании |
| `PRIVACY_URL` | HTTPS-адрес согласованной политики обработки данных |
| `TRUST_PROXY_HOPS` | Число доверенных proxy перед сервером; по умолчанию 0 |
| `RATE_LIMIT_PER_MINUTE` | Запросов в минуту с IP, по умолчанию 10 |
| `GLOBAL_REQUESTS_PER_HOUR` | Общий предел попыток запросов API в час на процесс, по умолчанию 200 |
| `MAX_CONCURRENT` | Параллельных запросов провайдеру, по умолчанию 4 |

Не меняйте модель или URL API без проверки совместимости: запрос использует `temperature`, `max_tokens` и формат `/chat/completions`.

## Развёртывание

1. Создайте Node.js веб-сервис на хостинге и подключите этот репозиторий после слияния PR.
2. Выберите Node.js 24; зависимости устанавливать не нужно. Команда запуска: `npm start`. Если платформа требует build-команду, используйте `npm run check`.
3. Введите `OPENAI_API_KEY`, `OPENAI_MODEL`, `PUBLIC_ORIGIN`, `COMPANY_NAME`, `CONTACT_URL`, `PRIVACY_URL` в настройках окружения.
4. Настройте HTTPS. Health check: `/healthz`. Этот маршрут проверяет доступность приложения, а не ключ и не AI-провайдера.
5. Проверьте диалог на адресе сервиса. Затем вставляйте виджет в Tilda.

Альтернатива — Docker:

```bash
docker build -t legal-ai-chatbot .
docker run --rm --env-file .env -p 3000:3000 legal-ai-chatbot
```

GitHub Pages не запускает Node.js backend.

### Proxy и лимиты

За proxy настройте `TRUST_PROXY_HOPS` по реальной топологии. Нельзя доверять произвольному `X-Forwarded-For`: выставляйте число hops только если backend доступен исключительно через доверенную цепочку proxy. При значении 0 за общим proxy посетители могут делить один лимит IP.

Счётчики находятся в памяти процесса, сбрасываются при перезапуске и не синхронизированы между экземплярами. Для нескольких экземпляров нужны внешние счётчики (например Redis) или ограничения на gateway. Глобальный предел не является денежным лимитом. Настройте ограничения бюджета у провайдера, мониторинг и при необходимости CAPTCHA с серверной проверкой. CORS не является авторизацией и не блокирует прямые серверные запросы.

## Подключение к Tilda

1. Замените `https://YOUR-BACKEND.example` в `tilda/embed.html` на HTTPS-origin вашего сервера.
2. Добавьте блок T123 «HTML-код» и вставьте этот короткий фрагмент.
3. Опубликуйте страницу и проверьте её на телефоне и компьютере.

Не вставляйте полный `public/index.html` в Tilda. `widget.js` сам создаёт кнопку и iframe с backend. Оформление чата не меняет стили сайта. Скрипт не вставляет пользовательский текст через `innerHTML`.

Iframe делает запросы на собственный backend: добавлять домен Tilda в CORS для такой схемы не нужно. Если вы устанавливаете дополнительные заголовки безопасности на хостинге, не блокируйте iframe через `X-Frame-Options: DENY/SAMEORIGIN`; настройте `frame-ancestors` с разрешением ваших доменов Tilda. На стороне Tilda политика CSP, если она есть, должна разрешать загрузку скрипта и iframe с backend.

## Данные и ограничения

- Сервер приложения не сохраняет тексты чата в БД и не пишет их в свои логи. История в браузере хранится только в памяти открытой страницы iframe; скрытие окна не очищает её. Кнопка «Очистить» очищает локальную историю, но не удаляет данные у провайдера.
- Последние сообщения передаются выбранному AI-провайдеру. Условия хранения провайдера и логи инфраструктуры необходимо проверить отдельно.
- До отправки интерфейс требует отметить ознакомление с передачей сообщений провайдеру. Этот элемент интерфейса не подтверждает выполнение всех требований к персональным данным и не заменяет юридическую проверку документов.
- Перед публичным запуском заполните контакты и политику, согласуйте основания обработки, локализацию и трансграничную передачу с профильным специалистом. Не отправляйте паспортные данные, номера карт, пароли и материалы, содержащие тайну.
- Нет CRM, записи на консультацию, загрузки документов, поиска по правовой базе или гарантии правильности ответов.
- Публичный endpoint остаётся целью для злоупотреблений. Ограничения в примере — базовая защита, а не гарантия безопасности.

## Проверки перед запуском

```bash
npm run check
npm test
```

Затем вручную проверьте настоящий API-ключ, повторную отправку после ошибки, мобильную версию, iframe в опубликованной Tilda, лимиты и ссылки компании. Автоматические тесты используют подставной ответ AI и не подтверждают доступность реального провайдера.

## Секреты

`.env` исключён из Git и Docker build context. Настоящий ключ вводится только локально или в секреты хостинга. Если ключ попал в коммит, отзовите его немедленно: удаление файла не удаляет историю Git.
